No new decision is invented merely to block planning. Existing local design acceptance is preserved. Unknown versions, real account schedules and actual human identities cannot be filled by an agent to make a demo pass. Where one readiness item is unavailable, proceed with unaffected developer-only work and state the blocked admission.

## First work packet

[examples/imp-00-work-packet.json](examples/imp-00-work-packet.json) is a planning-only handoff. It requests a baseline/source review and proposed redacted inventory/check matrix; it does not claim inventory results or authorize commands that start services/install tooling. The next authorized implementation action should be IMP-00's concrete read-only feasibility work, followed by the G-00 human review of pins/setup actions. Do not jump to bootstrapping a cluster or loading the model from the existence of this plan.

The first output should identify what the workstation already has, what remains unknown, expected ports/volumes/namespace separation and the smallest next installation/setup diff. Show why each tool is needed. When asking for a host/setup action, provide exact target, command category, expected effect, rollback and evidence; complete unaffected reversible design/test preparation first.

## Technology choices that remain intentionally small

Use uv/Ruff/Pyright and pnpm/Vite/strict TS testing baseline. Keep the explicit coordinator and DB-backed work tables rather than adding orchestration/message platforms. Prefer Kustomize for project-owned manifests, accepting upstream package templates only with rendered diff/provenance. Select the cluster/CNI only after workstation checks; this plan does not silently turn the preferred proxy family into an installed mesh or move deployment off the selected workstation.

Maintain an accepted usable manual baseline as optional AI and later capabilities grow. If the chosen model cannot satisfy a function or the host cannot meet the unmeasured concurrency target, present concrete reduced admitted-function/concurrency options and their effect on requirements; require an explicit change, not automatic fallback/substitution or concealed failed scope.
