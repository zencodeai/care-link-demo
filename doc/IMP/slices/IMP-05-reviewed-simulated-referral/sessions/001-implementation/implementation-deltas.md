# IMP-05 implementation decisions

The current user request activates IMP-05 source implementation and isolated automated qualification. It does not activate IMP-06, publish a change, deploy a live target, change host trust or admit participants. The accepted synthetic-only, no-police-integration and runtime human-authority boundaries remain enforced.

1. Canonical actor DTOs and 18 operation allocations remain the design source. Additive `ReferralSourcePage`, `ReferralContext` and `ReceiverDetail` projections supply authorized source selections, the current review version vector/expiry, and receiver-owned revision. They close missing UI discovery fields without accepting caller authority. `ReferralPayload` is explicitly exported for runtime validation. Metadata preflight carries the exact target, review ID, referral digest, consent and directory facts; final data authorization independently rebuilds them.
2. Manual source selections create immutable source-based draft identities, each generation 1. An edit requires a new selection/new draft and fresh consent/review checks; earlier uncertain dispatches remain intact. `ReviewCommand.edit` free text is rejected because canonical structured fields have no reviewed mapping from arbitrary edited text. The UI provides source-based replacement and accept/reject, with no implicit model author or machine review.
3. A separate authenticated worker send command pumps pending outbox intent. Each attempt has fresh guarded policy/consent/review validation, a monotonic fence, durable one-use authorization and pre-network consumed attempt. Global ordered guards serialize claims; there is no autonomous scheduler or timed lease reclamation in this slice. A restart/second call for attempted or unknown work reconciles the same dispatch ID. No lock spans receiver I/O.
4. The private simulator lookup port and strict signed receiver-envelope contracts are additive technical boundaries. Core signs exact receiver-audience requests backed by fresh identity evidence; the receiver independently resolves current identity and fictional-service assignment. Workload identity verification separates Core human routes from Data send/lookup routes. Receiver identity has only resolve/current access, including the review-origin composition branch; recovery and consent-proof stay denied.
5. Not-found/unavailable evidence never authorizes an automatic resend. The bounded implementation keeps reconciliation_needed and active support until further evidence or an explicitly new reviewed draft. No durable absence proof or safe reauthorization feature is claimed. Dropped responses reconcile by original ID, with durable deduplication and no duplicate package.
6. Referral, authorization, attempt and observation history is persisted separately. Canonical decisions/audits precede local effects. Receiver package/decision history lives in a separate credentialled database. Contradictory or malformed receipt evidence cannot become acceptance; sender state stays unknown and retains a safe observation. Received/partial/accepted never imply connected human support.
7. Sender and receiver content custody register atomically. Sender referral copies use referral purpose and `referral_terminal_parent`; session-only closure cannot make unknown work purgeable. Receiver copies record subject/session, encrypted locator, custody key, seven-day duration and pending `parent_and_delivery_terminal` anchor. IMP-08 remains responsible for coordinated later-parent/terminal-delivery anchors, rights and cleanup jobs. This slice claims registration and prevention of premature cleanup, not completed IMP-08 lifecycle work.
8. Source composition is explicitly opt-in and requires admitted signed technical simulator mapping, role-exclusive credentials and protected workload sockets. Existing live IMP-03/04 targets were not changed. Browser checks used real Chromium with mocked synthetic API/provider responses over loopback HTTP; backend tests independently used real TLS PostgreSQL, OPA, IdentityService signatures and gateway handlers with provider/mesh fixtures. No deployed HTTPS/MFA/native-200-percent or human review is inferred from those checks.

Human usability, screen-reader, visual and language observations are `deferred_until_after_IMP10` for GitHub issue follow-up. Automated results are separate from human acceptance and action authorization.
