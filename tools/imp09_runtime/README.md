# Isolated recovery composition

These adapters operate only against the named disposable IMP09 PostgreSQL fixture on loopback35439 with verify-full TLS. They do not configure or promote the existing demo deployment.

- `PostgresCaptureSource` exports a repeatable-read snapshot through pg_dump, including exact audit checkpoint, WAL position and immutable original capture time. EncryptedCaptures supplies authenticated encryption, manifest integrity and seven-day expiry.
- `PostgresRecoveryTargets` creates a separate database with PUBLIC CONNECT revoked. Each target has a unique NOLOGIN runtime credential in private maintenance custody. Import preserves exact existing ACL/RLS privileges; only enable grants target CONNECT and LOGIN. Source database control is fenced before routing. Maintenance and runtime DSNs are separate.
- Validation replays the intact current signed journal, verifies audit integrity, disables old access/continuations/consent/delegation/reviews/dispatch/inference, and retains holds/tombstones. Fresh external identity may re-admit basic principals without old ACLs/grants; a current journal identity/role fence always denies. Missing key or unknown restriction prevents validation/promotion.
- `IdentityRecoveryAuthority` requires a separately provisioned account-to-human mapping outside snapshots and fresh identity/provider checks. Same-person second accounts share a human ID. Purpose=promotion/resource=proposal MFA binds one exact immutable proposal, digest and expiry. It does not create a real approval merely by passing tests.
- `create_recovery_app` from core provides a separate private recovery-origin transport with cookie/Origin/CSRF and closed contracts. The frontend at /recovery uses the existing identity endpoints and additive read-only PromotionBinding evidence projections. Its browser harness uses synthetic API fixtures.
- `manual_target_app` injects BoundGenerationJournal into the gateway factory and checks the same admission at every edge operation/SSE projection. ManualService/dispatch retain final data/journal guard checks. An old raw-journal source process is also denied by the source DB fence. This requires explicit composition; none of the existing deployed services are rewired here.
- `SpoolHelpAuthority` and the internal help importer reconcile minimal status/revision/digest under current workload/journal authority and atomic canonical audit. They never restore assignment, story or connection.

Copy inventory includes imported databases and plaintext staging. Successful imports unlink staging dumps; interrupted copies remain accounted by the private registry or are detected as unknown databases. `expire_target` requires original expiry, fresh hold authority and a non-serving target; it drops only owned quarantine names and removes that target credential. Encrypted capture unlink is separate. Active serving storage follows ordinary lifecycle controls. Identity backups and help-spool copies retain their separate existing custody. No API claims universal physical erasure or automatically completes rights.request backup_pending.

Before a source-only test run, provision an owned private fixture with `python -m tools.imp09_verification.database start`; never reuse live/earlier lab databases. Run `python -m tools.imp09_verification.run_checks --attempt <unique-alphanumeric> --lane slice` and then source. The source lane requires the existing pinned OPA binary, project locked environment and disposable Docker fixture. Every attempt preserves its own logs, including failures.

Recovery drills use synthetic human actions; actual serving promotion still requires the distinct current human decision. Host custody must be explicitly supplied and fail on suspected loss/rollback. Readonly pre-admission probes verify current identity, audit, rights and DB generation; the integration test separately proves a real audited manual write after sealed admission using non-superuser target credentials. Its elapsed times include synthetic approval only, not real staffing delay, PITR/WAL replay, sustained RPO or deployment RTO.
