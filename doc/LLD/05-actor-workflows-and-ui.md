# Actor workspaces, service state and interaction algorithms

## Screen/action specification

The web application shares components, not credentials or privilege. Each route resolves its role session on the server; another role requires a new scoped login. Every command exposes pending/committed/unknown/rejected states and stable operation identity. Disable duplicate submission visually while preserving server idempotency. Never show an optimistic private send/assignment/consent success before durable acknowledgement.

## Session and turn algorithms

Session orthogonal fields: service phase `active,human_requested,queued,worker_assigned,handoff_pending,human_controlled,ended`; transport `connected,reconnecting,disconnected`; accountable owner plus monotonic control_epoch; degraded_reasons set; attributed outcome events. Project `degraded` as a visible capability overlay while retaining actual phase. A disconnected browser or receiver does not prove case resolution or human disconnection unless channel evidence establishes it.

Create validates issued participant, tags/role/jurisdiction/channel/locale. With persona_id=null it allocates a new synthetic persona of the declared participant kind and preexisting subject guard, then session+guard+own ACL+event and canonical audit in one gateway transaction; returns authorized persona_id and subject_id. PID session subject is its new own PID persona. Carer/professional-participant session subject is its own report persona, never an implicitly linked PID. A referenced existing persona requires an explicit existing own binding; otherwise deny. Cross-subject fixtures use separately provisioned synthetic subject/ACL/delegation, never metadata matching. Assessment is unavailable until a ≤60-word reviewed disclosure is acknowledged (speech simulation ≤30 seconds). Human request/static links remain accessible. Unknown jurisdiction permits intake and human request but blocks a jurisdiction-required referral until explicitly supplied.

Turn sequence: acquire idempotent command identity → current access check → append user turn/assertions with capture/unknown/deferred labels → run deterministic fixture hazard/youth/unknown/tier/escalation rules → commit assessment revision, controlled rationale/template references and routing intent → optional task preparation. Model call never precedes urgent handling. `situation_factors` remains exactly `{}`; fixture selection is made by authorized scenario configuration, never model text. Proposed fixture priority maps T4→0,T3→1,T2→2,T1→3,T0→4; it is a test ordering, not clinically validated triage. Minimum T2, critical unknown, age-uncertain, 10 assessment turns/10 active minutes or 2 invalid proposals request human routing per parameters. Silence does not trigger risk or termination.

`correct_fact` appends a superseding attributed assertion; `disagree_rationale`, `decline_option` and `choose_alternative` are distinct commands/events. None cancels mandatory deterministic escalation. Disputes preserve both assertions and notify an authorized worker. Rationale is assembled from fixture rules and approved sourced content, never hidden model reasoning. Guidance units are ≤25 reviewed words and one action; persistent AI/stub labels are separate from guidance text.

## Human request, assignment and handoff

Human request can occur in any non-ended phase regardless of model availability, optional tool budget, assessment completeness or referral consent. Under session guard return existing active ticket or create one; duplicates never reset requested_at or priority. Queue scheduler moves human_requested→queued; display pending if scheduler is unavailable, not false connection. Queue modes: regional outage overrides partner unavailable, then severe waiting≥6, elevated 3..5, normal≤2. Fixture partner flags override load. Stable selection `(fixture_priority,requested_at,ticket_id)`; model cannot change it. Update status every 60 seconds, fixture reassessment every 120; ETA null without live evidence.

Reservation locks queue/session and verifies worker eligibility; proposed 60-second reservation expiry is measured/reviewable. UNIQUE active assignment permits one reservation. Acceptance requires current reservation/revision and sets worker_assigned, not connected. Prepare transfer creates scoped context and worker acknowledgement; sets handoff_pending. Confirm transfer requires matching current assignment, worker acknowledgement and actual two-party channel evidence within a proposed 30-second evidence lifetime. One commit sets accountable owner, human_controlled, increments control_epoch and fences prior system/worker output. Failed/refused/dropped transfer releases/requeues as appropriate, keeps support and never sets ended. A confirmed handoff can close the automated segment; whole session closure is separate.

Observe scope is explicit and expiring, never writer authority. Takeover is supervisor command bound to target worker and current revision; increment control_epoch atomically, stale all old-owner task/delivery leases and consequential reviews. If no connected channel evidence, show assigned/handoff_pending, not human_controlled. Every send and output release checks current owner/epoch. Bytes authorized before takeover may already be in transport; record that fact, never promise recall.

Explicit participant end records user choice and unresolved status, removes pending optional work, and closes own session; system timers/silence cannot end unresolved T1+. Mandatory human support is retained until explicit user end or confirmed transfer of the relevant segment. Ended session cannot be resurrected by retry/job; a new interaction needs new session authority.

## Youth, follow-up and outcome

Every age-uncertain/youth fixture turn offers discreet private help where simulated channel supports it. Creating a private session is a new ACL scope; contacting adult obtains no notifications, transcript or location by relationship. Human routing is a project role-play mechanism. Real youth capacity/reporting/legal rules are disabled; reviewed stub content says so.

Follow-up anchor is an explicit client/worker-recorded post_crisis_event, never silence, session start or mere connection. Unknown anchor→anchor_pending. Separate contact consent names subject, internal recipient, purpose and expiry. due_at must be24..72 hours after anchor; proposed delivery expiry=anchor+72hours. Test clock controls only synthetic business scheduling, never authentication/consent/security expiry. Claim due job, then current contact consent/opt-out and audit authorization; deliver to internal inbox with stable effect key. Cancel before authorization stops delivery; after authorization may be too late and must display truthful status. For unknown delivery, query stable inbox key. A durable absence proof plus fencing of every previous sender/authorization permits fresh authorization with the same inbox key while consent/window remain valid. Otherwise retain reconciliation_needed; proven absent opt-out/expired work may become cancelled/expired, never infer absence from timeout. Carer support has its own attributed outcome.

Outcomes append offered/chosen/declined/attempted/received/accepted/connected/reported_benefit/unknown with reporter/time/source. Assistant/task completion cannot create care success. Alternate failed/successful pathways remain visible. Lack of follow-up is unknown, not no-harm or success.

## Accessibility and reconnect

EN-CA/FR-CA reviewed catalogues share semantic message keys. Missing translation disables affected content rather than invoking unchecked translation. Keyboard/screen-reader labels, error association, focus restoration, contrast, reduced motion, discreet help and low-bandwidth views are tested. New stream entries use polite live regions without stealing focus. Silence prompts at 120 seconds then configured300-second repeat, with silent mode and no pressure; a30-minute silent fixture must preserve unresolved state. Reconnect performs current authorization and snapshot resync; no private offline cache, hidden identity linking or assurance increase.

## Two-party channel confirmation protocol

Prepare-transfer creates a durable channel challenge bound to session, assignment, control_epoch and transport generation, with separate random participant/worker nonce hashes and 30-second expiry. Each independently authenticated current endpoint obtains only its own challenge nonce and acknowledges through the typed channel-ack operation over its current BFF transport. Party identity is server-derived; guessed IDs or caller party labels cannot substitute. Persist unique(challenge,party) ACK with principal/browser-session digest and transport generation. Only both current ACKs, live server channel state and unchanged assignment/epoch produce channel_evidence with both ACK refs and expiry. TransferConfirm resolves that exact evidence and worker ACK under session guard; nonce replay, old transport or disconnected/expired party fails. This establishes a supported app-channel handshake, not clinical benefit or a real carrier connection. Lost nonce response requires replacing/fencing the challenge, not reissuing a guessed secret.
