# G-10 protected deployment bindings

The protected role launcher now starts the separately configured Training and private Help processes. Core binds the signed Training and Evaluation routes in manual and assisted modes. Data loads the pinned replay catalog. Both protected Identity surfaces can admit the Training proof audience and bind the distinct Help browser origin. Feature selection is explicit, and ordinary launch configurations retain their existing route set. [Role configuration](../../../../../../tools/imp10_runtime/README.md)

The image smoke exercised the real protected Unix socket from two Linux UIDs in a disconnected container. The assigned proxy UID received the Training shell. The other UID received 403. A replay request from the proxy UID without a session received 401. Image file hashes matched the checkout for the recorded role sources and assets. [Packaged launcher evidence](evidence/protected-image-smoke.json)

The offline mesh renderer derives both directions from the protected route graph and emits separate Envoy and authorization files. Runtime has Core egress only. Help has a separate browser origin and Identity egress. Browser listeners reject internal paths. The pinned Envoy parser accepted all eleven generated role configurations with networking disabled. [Mesh validation](evidence/mesh-config-validation.json)

The final regression run passed 38 of 39 commands, with 1,792 backend tests and 234 frontend tests passing. The existing IMP-08 policy latency test measured 53.407 ms p95 against a 50 ms limit. It measured 40.169 ms on an isolated rerun with the same limit. [Source checks](evidence/source/checks.json) · [Latency measurements](evidence/source-latency.json)

The first live Qwen loopback run hit the configured inference deadline. The serial retry passed with ten active sessions, two occupied inference slots, and eight queued tasks. Both warm Runtime requests reached human review in about 18 seconds. The retry also exercised five listener faults using the loopback fixture. The disposable TLS database and credentials were removed after verification. [First attempt](evidence/live-combined-first-attempt.log) · [Live retry](evidence/live-combined.json) · [Cleanup](evidence/cleanup.json)

**G-10 remains open.** The deployment still needs an isolated provisioned profile with independently registered workload identities, verified-TLS stores, exact OIDC and replay policy inputs, and the approved model qualification bindings. Run the protected role and dependency probes, private Help continuity, and repeated cold, warm, and error checks at ten sessions on that profile. The earlier Kind outage and CNI checks retain their developer-image scope.
