## Corrections and rechecks

The initial live application journey tried to renew a lease during its final inference wait. Runtime now consumes an already-completed result and skips lease renewal when its existing deadline has elapsed. The original provider exception still propagates. Three deterministic tests cover pending work, a completion race and a provider timeout. An initial mesh attempt exposed a Data fixture that lacked the new optional replay evaluator attribute. The fixture explicitly leaves replay disabled. An intermittent Docker CLI startup timeout also left an owned proxy appearing after the error. The lease registers its expected container name before creation and validates the exact label before cleanup. The recovery used only resources from the current attempt and removed them afterwards. [Runtime and cleanup regressions](evidence/runtime-mesh-regressions.log)

The first broad run alongside mesh activity recorded four database test failures and a separate manual setup deadline in the fixture-provider comparison. Each failed database case passed when rerun separately from mesh work. Saturation and the fixture-provider comparison also passed in that recheck. The temporary PostgreSQL clock probe measured a database timestamp up to about 70 ms behind the host send timestamp and round-trip variation. This measurement occurred after the failures and cannot establish the cause of an individual failure.
