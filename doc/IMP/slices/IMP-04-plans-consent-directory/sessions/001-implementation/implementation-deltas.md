# IMP-04 implementation contract deltas

These source extensions resolve concrete transport gaps without changing REQ/HLD/LLD files or granting new actor authority. They are generated by `tools/generate_contracts.py`, enforced on both sides of the gateway and included in independent review.

| Delta | Reason and boundary |
| --- | --- |
| Optional closed `MetadataRequest.planning` discriminated union | Carries the logical operation ID and exact typed public arguments/path IDs for the eleven IMP-04 operations. The signed hint lets data discover the session/subject and original replay anchor; authoritative locks, facts and ACLs are still rebuilt there. |
| `MetadataResult` resolved scope, consent/source bindings | Core's preliminary PDP request receives the same server-derived fields, recipients, grant references and source versions. No content values or permission cache are returned. |
| `PolicyInput.disclosure_grants`, scoped consent-evidence fields, directory bindings and revision-set digest | A PlanView may depend on several exact grants. Policy requires every emitted field to be covered and binds subject/session/purpose/recipient. Directory bindings preserve exact immutable source revisions/artifact identities. The final guarded command recomputes the complete input. Informational stale/quarantined listings are permitted only with conservative projections; no dispatch operation is added. |
| `own_reports_read` / `GET /v1/sessions/{session_id}/own-reports` / `OwnReportPage` | Returns only the current account's attributed assertions for its own authorized session/subject. The finite projection rejects history overflow rather than silently omitting rows. It grants no shared transcript, PID edit or workforce access. |
| `StepUpStart` purpose `follow_up_consent` | The canonical grant DTO has follow-up purpose but the ceremony enum lacked a matching action. This separate subject-bound MFA purpose supports the consent operation; it does not schedule, send or activate follow-up. Plan maps to existing `plan_edit`; referral maps to existing `referral_consent`. |

Path IDs participate in mutation idempotency digests. Replayed views resolve current grants/sources; searches regenerate the current page under the same logical key, and a changed payload/target conflicts. Explicit negative rights remain available without an edit-level step-up. New proof resolution is an internal data-workload-only route; exact browser cookies, provider status and original evidence deadline remain in identity custody.

The small demonstrator keeps the predecessor's global control guard and ordered final checks. This serialization protects missing rows as well as existing rows. Immutable repository writes use INSERT-only SQL and skip unnecessary row-update locks. Plan lifecycle copies remain associated with their originating session for custody/RLS but have independent purpose and retirement anchors.

Engineering fixture signatures and the policy bootstrap are integrity evidence with `human_review`/`human_acceptance` and participant admission false. Source key pins are independent trusted composition inputs. The accepted IMP-03 policy/bootstrap remain byte-for-byte unchanged; IMP-04 has its own candidate files. No source-content URL is fetched or converted into a destination.
