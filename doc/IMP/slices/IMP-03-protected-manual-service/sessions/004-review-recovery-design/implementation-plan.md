P0/P1 are the first bounded implementation packet. P2 depends on their context/ownership contract; P3 and P4 integrate on that contract. At most three specialists concurrently, no nested agents. Primary serializes schema, migration, policy, lockfile and deployment changes. Do not implement an operator dashboard, general tenancy platform or purge system in this effort.

## Contracts to settle before their implementation step

1. Exact trusted origin/run/slot binding, server session ownership and provider account-match semantics; preserve fresh proof and exact callback validation. Decide the scoped DNS/certificate/browser-trust setup before P2 deployment.
2. Authoritative workspace, own assignment revision, non-secret routing and read-only handshake summary; no guessed revision/ownership from UI state.
3. Encrypted draft/submission intent lifetime, per-revision idempotency, conflict rules and same-principal recovery; final authorization still rechecks all current rights.
4. Channel lease scope, observer behavior, explicit transfer, reconnect/backoff and handshake invalidation; observers cannot count as either party's confirmation.
5. Guarded run membership/admission, queue scope and active/closing/closed semantics. Closed runs retain exact same-principal status-only recovery, while all business commands deny; preserve unresolved support and old journal/fence evidence.
6. Toolkit registry/secret-reference schema, locks, command receipts, resumable provider rotation and compatibility migration policy.

These are finite implementation inputs. They do not authorize recreating doc/LLD or changing canonical HLD/IMP scope.

## Acceptance matrix

All journey cases use visible actor controls and real issued identities. API/unit tests supplement the journey. Do not preseed cookies, fabricate roles, use separate actor contexts or bypass disabled controls for the same-browser acceptance lane.

| Case                          | Required observation                                                                                                                                                                                        |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Warm browser, fresh run       | Start run A, then B in the same browser/profile without clearing anything; B has new scenario state and explicit identity/run labels; A remains preserved                                                   |
| Cold browser state            | Fresh/cleared browser storage leads through sign-in and reconstructs B from the toolkit/server; clearing authentication legitimately signs out but loses no durable scenario/operation state                |
| Four actor tabs               | One shared browser context, four pages, real provider login/MFA; participant, worker1, worker2, supervisor stay exact even when login order changes and starts overlap                                      |
| Existing provider SSO         | A previous provider account cannot silently populate a different slot; wrong-account callback yields no private output                                                                                      |
| Local sign-out / expiry       | One slot expires/signs out; other slots continue; same-principal reauth restores authorized work                                                                                                            |
| Reload / full OIDC navigation | Restore own assignment and saved draft; interrupted callback has a clear resumable/restart outcome; no UUID copying or cache-clearing instruction                                                           |
| Duplicate tab / reconnect     | Observer does not replace the active channel; explicit transfer fences old ACKs; repeated stream loss does not oscillate or fabricate connected status                                                      |
| Unknown durable send          | Lose reply after commit, reload or reauthenticate, recover the original server-held operation; exactly one logical message/effect and canonical audit outcome                                               |
| Handoff pace and expiry       | Both actors see required next action and time remaining; expiry/reload permits explicit fresh preparation; no stale nonce reuse or implicit ACK                                                             |
| Complete manual journey       | Visible intake/disclosure → request → worker reserve/accept → two-party confirmation → attributed exchange → supervisor scope/takeover → old-owner rejection                                                |
| Run boundaries                | Cross-run URL/resource, forged host/slot, old business session and closed-run business commands deny; exact-principal status recovery works after a close/unknown-send race; old unresolved records survive |
| Credential lifecycle          | Missing vault entry fails clearly; rotate only named actor; crash between provider update and local receipt resumes without silent reset or cross-actor effects                                             |
| Lifecycle readiness           | Exercise at least one real SVID renewal and public authority-bundle rotation with the environment steward; no timed chat maintenance dependency or manual restart required to continue                      |
| Browser/cache/build matrix    | Chromium shared-context automation; native Safari human check; cold and warm HTTP caches, back/forward and asset-version transition all bootstrap current server context                                    |
| EN/FR accessibility           | Role-appropriate wording, keyboard/focus, announced errors, visible recovery and truthful pending/unconnected states in both languages                                                                      |

Freeze pass criteria before running: three consecutive from-scratch runs in the same retained browser profile with no developer repair, no storage clearing and no unexplained actor/connection changes; all protected adverse assertions hold. Include one run that crosses credential/trust lifecycle events. Automation in Playwright WebKit supplements but does not substitute for the native Safari check. Browser certificate verification stays enabled.

## Stop conditions and evidence discipline

Stop qualification at the first unexplained identity switch, disappearing recovery controls, duplicate durable effect, cross-run private disclosure, trust-renewal outage or required operator repair. Preserve redacted diagnostics with run/slot, build/contract versions, request correlation and stable operation IDs; never capture credentials, token URLs or message bodies in public evidence. Route the defect to its owning step and review the design if a bounded correction fails the same case again.

Use one short current run result and one candidate manifest linking targeted evidence; keep raw logs private. Historical packet bytes and scoped deployment acceptance remain unchanged. Product progress must be measured by the matrix, not by growing test totals or repeated human retries.

## Decisions and next authorized action

Recommended defaults are registered actor hostnames, one active run per leased environment, durable local CLI with OS secret storage, authoritative workspace/draft/intent recovery, and an explicit interactive-channel lease. Hosting/certificate/provider configuration and any later live mutation need their own exact reviewed delta and authorization. No such change is executed here.
