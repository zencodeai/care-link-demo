# Protected manual data gateway

IMP-04 adds cohesive `plans`, `consent`, `directory`, `directory_admission` and `planning_policy` modules behind this gateway. Migration `003_plans_consent_directory.sql` is additive and requires separate migration custody. Construction accepts a `VerifiedDirectoryAdmission` built with independently pinned source keys; unsigned feed booleans confer no admission. Current policy scopes and final disclosures bind exact fields, recipients, grant evidence and source revisions. Shared output is checked again after projection. Active plan copies use an independent retirement+30-day lifecycle anchor. See the [source handoff](../../doc/IMP/slices/IMP-04-plans-consent-directory/sessions/001-implementation/handoff.md) for actual checks and pending live qualification.

`care_link_data.ManualService` implements the IMP-03 manual domain boundary. `PostgresStore` alone receives the business PostgreSQL DSN; it requires pinned-CA `sslmode=verify-full`. Constructor injection supplies fresh identity, OPA policy, separately credentialled current host journal, live endpoint registry and encrypted content custody. Construction has no connection/migration/import-time side effects.

Apply `migrations/001_manual.sql` separately as the migration owner in a specifically assigned database. It creates additive native authority/domain/operation/audit/lifecycle records, forced session row security and separate non-owning runtime/audit-reader/backup roles. `bootstrap` and `provision_principal` are offline migration-owner hooks, absent from HTTP. Runtime has no DDL/TRUNCATE/DELETE, principal provisioning or audit-event mutation. An owner/superuser or compromised gateway remains outside the protection provided by these grants; transaction-local RLS context is gateway-derived defense in depth.

Every protected operation prepares metadata/PDP outside final locks, then takes the global control guard, sorted principal guards, subject guard, session guard, domain/operation rows and finally audit head. Current identity/role/own ACL or assignment, policy binding/version/deadline, journal identity/generation/barrier and serving generation are rechecked. Business state, stable operation identity, reference events and canonical audit commit together before bytes are released. The signed policy decision must include exactly supported `audit_before_effect`; unknown obligations deny. A failed or uncertain dependency never releases protected success. Terminal rejected keys remain rejected; lost commit acknowledgement uses the same key/status and fresh authorization.

The global guard intentionally serializes this small demonstrator. SQL calls have 900ms lock/statement limits; the application retains an original 1000ms authorization budget and the policy decision's shorter expiry. This is a bound/check, not a measured latency SLO. Psycopg/explicit ordered SQL follows existing identity adapter practice; SQLAlchemy/Alembic integration remains an explicit engineering implementation delta, without an authority/schema rollback claim.

Participant creation allocates its own synthetic persona/guard/ACL. A supplied persona must already belong to that principal and participant role. A fixture ID must match separately supplied `scenario_bindings`; model/browser text never selects escalation. Disclosure acknowledges exact configured template bytes before assessment. Turns are attributed/encrypted and use deterministic stub fixtures with empty `situation_factors`; missing critical fixture information requests human support. Human request works before disclosure and without AI. Explicit user end preserves unresolved outcome; silence or disconnection has no end path.

Workers reserve metadata queue entries, accept their own reservation, and read only current assigned context. Acceptance is unconnected. Prepare creates a 30-second challenge; each independently authenticated endpoint obtains one nonce response, stored as a hash only. Lost/repeated nonce reads require new preparation. Both ACKs bind browser session, transport generation, identity/role revisions and live server channels. Confirm checks both current principal guards and exact ACK/evidence/assignment/epoch before setting human control. Supervisor observe/interrupt is expiring and read only; explicit takeover advances epoch and requires a new handshake. Later old-owner sends/events deny; already authorized bytes cannot be recalled.

Revision bindings are explicit: reserve and first observe use `QueueView.revision`; accept/prepare use `AssignmentView.revision`; confirm, takeover, failed transfer and participant commands use current `SessionView.revision`. A takeover's newly accepted assignment starts at the returned session revision, allowing its target to prepare a new challenge. Observe returns canonical `CommandResult`. Same-key ACK replay rebuilds only the current caller's ACK/evidence after fresh authorization/audit.

Queue/message pages use signed principal/filter/expiry-bound keyset cursors. Event storage contains references, never serialized transcript payloads. `session_events` releases at most one freshly authorized/audited reference per call; over-32 backlog, cursor gap or invalid position requires resync. The transport must call again before each next delivery and maintain actual endpoint liveness.

Continuation custody is digest only and carries AL0. Rotation spends the current token and returns its replacement once. Same-key replay returns `OperationStatus(state=replacement_unavailable)`; it never reconstructs a secret. Fresh same-principal proof binds recovery to the exact known session/family. A root lineage plus unique active-family constraint lets a fresh recovery from a known ancestor fence an unknown successor after a lost recovery response, then issue one replacement. Recovery can accept a known older family revision only with that new exact fresh proof, since recovery itself may have advanced it in the lost response. The additive local `continuation_issue` operation exposes initial issuance without changing SessionView; `continuation_bootstrap` is only a compatibility helper calling that same protected use case.

`authority_metadata` returns current minimized guard facts/versions after fresh authority/barrier/audit and never content. Public transport must independently verify its signed `MetadataRequest` delegation. Internal `restrict_principal` and `review_queue` are explicitly local helper actions (`manual_identity_restrict`, `manual_queue_review`), not substitutes for canonical workload `Signal`/`DueJob` operations. They exercise journalled principal fencing and bounded reservation-expiry/queue review; canonical `DutyCommands.identity_revoke(Signal)` and reservation-only `job_execute(DueJob)` now supply the separate machine path. The signed duty registry defaults to disabled until exact admitted receipt/artifact bindings and current certificate/fence callbacks are supplied. `duty_app.create_duty_app` exposes only the named typed internal routes.

`AESGCMContentCipher` requires an explicit 32-byte key, uses random per-value nonces and versioned associated data, and exposes only a stable domain-separated key fingerprint. Session/content copies register purpose, exact parent, encrypted locator/custody reference and pending lifecycle anchor. Explicit parent closure sets the original seven-day retention deadline; no purge/physical erasure is claimed. Canonical audit hashes are recomputed inside the narrow append function and verified by `verify_audit_chain`; operator has no standing transcript/audit read grants. Recovery-critical restrictions journal intent before DB effect, so journal-success/DB-failure fences later protected work. Full restriction reconciliation/serving restore remains separate.

Run deterministic custody tests with the normal suite. PostgreSQL tests require explicit `CARE_LINK_MANUAL_TEST_DSN` for an isolated TLS fixture. They refuse an existing `imp03_manual` database, create only that owned database/test roles, and clean them after the session. Never point them at the accepted IMP-02 lab. The initial data suite uses labelled authority/policy/journal/channel doubles to isolate database mechanisms; composition tests separately bind real OPA, signed journal, live channel registry and browser transport. No test or signature supplies human G-03 acceptance or participant admission.

Current connection flags are projections of the exact confirmed assignment/challenge and both current endpoint/ACL/revision predicates, not merely historical human_controlled phase. Loss of a transport keeps the owner and unresolved support while reporting disconnection.

The IMP-03 remote HTTP transport locally extends `Gateway_session_events.arguments` with required canonical `last_event_id`. Its cursor is therefore included in the delegation's body digest; an inconsistent `Last-Event-ID` header denies. The browser SSE header remains unchanged. This explicit internal transport compatibility change is generated without editing frozen LLD definitions.

Workload audits preserve full actor_context. A verified denied duty produces canonical DENY after rollback when audit is available; uncertain commits reconcile separately. Test registry/signing receipts are explicitly synthetic fixtures, never runtime admission or human approval.
