# Bounded local inference

The runtime sends closed task/step/fence references to Core. `RuntimeClient.run_one_turn` runs a reference-only LangGraph lease/inference/proposal sequence with lease renewal at most every five seconds; it does not retry generation, invoke proposed tools or send communications. Core uses its stored initiating actor, fresh signed identity evidence and a task-bound delegation to the data coordinator. Context and release pins are rebuilt from current server-owned sources. Inference alone calls the authenticated host bridge; the bridge has one fixed loopback LM Studio completion endpoint and the exact `qwen/qwen3.8-27b` identifier.

`HttpCoordinator` and `RuntimeAuthenticator` bind the entire request, operation, path, task and observed runtime certificate/fence metadata to the Core signature. `StoredInferenceAuthority` independently rebuilds context inside the data boundary. `HttpContextAuthority` and `HttpJobLedger` give inference fixed data endpoints without database credentials. The gateway rechecks current authority before delivery. The model returns bounded evidence indices. Trusted gateway code reconstructs task identity, SourceRefs and exact text, requires all patient assertions and validates the full canonical unsent proposal; the model cannot send a referral or grant consent.

`PostgresJobLedger` owns two persistent compute slots. Unknown compute remains occupied across restarts. Only observed completion or separately authenticated stop evidence can release it. The initial adapter immediately denies new work when both slots are occupied: its waiting queue is zero, within the design ceiling of eight. Runtime/model transports expose no stop or reset method. Manual requests do not wait on inference locks or queues.

All default functions are disabled in `config/demo/assistance/model-manifest.json`. Structural tests and mocked provider replies do not admit the selected model. Actual artifact origin/digest/license/quantization, loaded identity, server/engine, exact tokenizer/template, output-schema and per-function EN/FR/grounding/adversarial/latency evidence remain required. The inference application uses `HttpTokenCounter` exclusively through the authenticated fixed host bridge `/internal/v1/inference/tokenize` endpoint. Its proof binds exact loaded model ID, loaded artifact SHA, tokenizer/template identities, window and request content digest. Host-only `LMStudioTokenCounter` applies the already-loaded SDK handle’s actual prompt template and tokenizer, rechecking those identities before and after counting. Tokenization has a ten-second response deadline and two owned slots; a timeout retains the underlying slot until counting actually finishes. Session003 installs pinned SDK1.5.0 and binds the already-loaded Qwen instance. Actual server-rendered nonthinking templates are obtained using the pinned SDK generated RPC/vendor configuration seam, then tokenized and matched to REST `reasoning_effort=none` prompt counts. Template drift denies output. No character estimates or model autoload are used. SDK-internal compatibility and enforced server authentication remain explicit deployment/admission obligations.

The deliberate OWASP2025 baseline is retained. `threat-sources.json` pins verified official OWASP and ATLAS data revisions and content hashes; `threat-map.json` links each disabled function's applicable risks to structural enforcement/tests. The additional `agentic-threat-map.json` records the OWASP Agentic Applications2026 and Securing Agentic ApplicationsV2 crosswalk for this implementation, without claiming certification.

Automated verification uses `uv run --locked --all-packages pytest services/inference/tests services/runtime/tests host/inference-bridge/tests tests/evaluation`. The durable/source-context tests in `services/data/tests/test_assistance_jobs.py` require the explicit disposable TLS PostgreSQL fixture. Test receipts distinguish real PostgreSQL, actual Ed25519 signatures, transport doubles and real-model evidence. Human review remains deferred until after IMP-10; no clinical, real-partner or production claim follows.

`python -m care_link_inference.evaluation --output <receipt.json>` only probes the existing loopback `/v1/models` endpoint and records availability/evidence gaps. It does not start the server, load a model, send prompts or admit a function. `evaluate_cases` runs synthetic cases through an explicitly composed generation callable and retains digests/latency rather than model reasoning.

SDK interface reference verified on 2026-11-20: [LM Studio Python tokenization](https://lmstudio.ai/docs/python/tokenization) documents `Chat.from_history`, `apply_prompt_template`, `tokenize` and `get_context_length`. This source is an interface reference, not an installed SDK/version or selected-model proof.

Session003 actual tests passed four EN/FR clinical-reference/injection cases with exact source grounding, zero reasoning tokens and matching prompt counts. Earlier schema and reasoning failures are preserved. Default admissions remain disabled; a current release must bind the evaluated catalog, canonical/wire schemas, prompt, render mode and code/artifact identity. This is technical preadmission evidence, not clinical or deployed-isolation qualification.

The first selection profile accepts at most12 selected entries. More than12 mandatory patient assertions produces `reduce_scope_required` before tokenization/provider work. Runtime state has no model client, patient corpus, independent checkpoint store or cloud tracing; all execution goes through fixed authenticated broker ports.
