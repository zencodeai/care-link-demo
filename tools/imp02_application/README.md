# IMP-02 application composition

`python -m tools.imp02_application --role identity|main|help|static --config /config/<role>.json` starts exactly one selected application behind its assigned protected Unix socket. The isolated lab supervisor owns socket directories and role UIDs; the application verifies its directory ownership and never creates an unprotected TCP backend.

Identity owns PostgreSQL/provider credentials, encrypted bearer custody and signed short-lived authority. It exposes separate main/help BFF contexts on exact mesh routes; main/help forward only the listed browser protocol routes through a pinned local Envoy egress socket. Incoming headers cannot supply workload provenance or private help proofs. The local socket carries HTTP; the actual Envoy hop performs SVID mTLS. `MeshTransport` refuses every other authority. Browser cookie hostnames are distinct because ports do not scope cookies. Main still exposes the IMP-01 developer capability and unavailable business API.

The `prepare` module creates only external ephemeral credentials/PKI in a fresh owner-only temporary directory. It does not install trust roots, change DNS, or start services. `PinnedAddressTransport` supports temporary address mapping with the original verified HTTPS SNI and CA. `database.configure` is an initial-only migration utility; it refuses to adopt an existing identity database. The runtime gets DML only, no schema/database creation or temporary-table grant. Provider provisioning and retention qualification are explicit coordinator invocations, never browser endpoints.

These adapters are for the named private synthetic engineering lab. They grant no real participant admission, clinical approval or G-02 acceptance. Actual resource bindings and verification results belong in the session evidence, not inferred from these sources.

Owner access-review recovery is narrowly available through `python -m tools.imp02_application.maintenance begin|complete|approve|decline --config /config/identity.json --owner-account-id ACTUAL_MAIN_UUID --state OWN_0700_DIR/review.json`. It writes the short-lived provider authorization URL only to the private state file. The operator opens that URL, completes real fresh MFA, and supplies the resulting exact main callback URL to `complete` via stdin. The ordinary BFF deliberately rejects this maintenance purpose before code redemption. `approve`/`decline` records an explicit owner decision; it never issues a browser session or changes roles. The file is removed after confirmation. Run in assigned identity custody; expired/incomplete intent secrets are disposed through the retention lifecycle.
