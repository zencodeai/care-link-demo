# Protected IMP-10 role composition

Start one role with `python -m tools.imp10_runtime.serve --role <role> --config <absolute-owner-only-config.json>`. Supply `session: imp10-protected`, the exact `role`, the process `uid`, a distinct `proxy_uid`, and an absolute `backend_socket`. The backend socket directory belongs to the application UID and proxy group with mode `0710`. The application runs unprivileged behind the protected Unix-socket proxy. Provision the existing role-specific Identity, Data, policy, journal, and browser inputs under separate custody.

Set `training_enabled: true` independently on Core, Data, Identity, and Training. Core needs its `outbound.training` mesh socket and origin in addition to the existing Data, Identity, and policy routes. Core exposes `/training` and the signed scenario and replay routes. Training receives `outbound.identity` and its own verified-TLS PostgreSQL DSN, migration `002_training.sql`, private `content_key`, distinct `core_public_key` and `identity_public_key`, and exact `training_artifact` and `training_policy` pins. A pin contains an absolute `path` and a lowercase `sha256`. The version-one policy names admitted trainer UUIDs and their exact scenario action subsets.

Data needs migration `013_imp10_evaluation.sql`, the exact `training_artifact`, and a pinned canonical `replay_catalog`. The version-one catalog binds the installed runner, artifact and contract bundle digest. It lists admitted captures with `owner_id`, `reviewers`, and the pinned `manifest` and `observations`. Use the existing `admit_completed_capture` helper to obtain the recorded output of a committed Training scenario. Configure the separately admitted evaluation policy in the existing PDP. Changing a capture or catalog requires a new explicit pin and process start.

Enable private Help on Identity with a `help_identity` object containing its distinct HTTPS `origin` and `oidc` client configuration. Use the same admitted issuer with a distinct client ID and secret and the exact Help callback. Launch Help independently with its `identity_origin`, `origin`, `static_origin`, `outbound_socket`, `spool`, Identity receipt `signing_key_id` and `signing_public_key`, and built `web_directory`. Help uses its own browser cookie and requires current Identity authority for every private operation.

Use `tools.imp03_runtime.config.protected_routes` for the opt-in non-assisted backend and proxy path allowlists. Assisted Core and Data also use the optional training routes in `tools.imp06_runtime.routes`. Keep the Training peer limited to `resolve` and `current` on its exact Identity audience. Help’s peer can use the named Help browser and authority routes. The existing assisted launcher retains its reviewed serving release requirement. Mount separate role configs, socket directories, trust bundles, workload identities, and stores on the target topology. Runtime retains its existing Core broker-only egress.

Render the matching proxy and authorizer configurations with `python -m tools.imp10_runtime.mesh --bindings <absolute-owner-only-profile.json> --output <new-directory>`. The profile declares `session: imp10-protected`, the four boolean `features` (`assisted`, `training`, `referral`, `help`), the immutable `pins`, and exactly the enabled `roles`. Pins contain `envoy_image`, `envoy_version`, `spire_image`, `spire_version`, and `svid_ttl_seconds`. Each role declares `spire_socket` and its exact `outbound` map from destination role to Unix socket. Private listeners also declare `address`, `port`, `backend_socket`, `authorization_socket`, `authorization_uid`, `trust_bundle`, `proxy_uid`, `fence_socket`, and `fence_uid`. A separate `dial_address` can bind the admitted peer dial endpoint. Core and Help declare a `browser` with its own `origin`, `address`, `port`, `certificate`, and `private_key`. Help also declares its `backend_socket`. The resulting Runtime configuration has its Core egress listener only. The Help configuration has browser ingress and Identity egress. The renderer writes configuration files for the separately provisioned workload and fence authorities.
